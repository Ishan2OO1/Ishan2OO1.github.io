MedQGraph

A clinical decision-support system that turns six MIMIC-IV v3.0 modules into a Neo4j temporal knowledge graph — 230,000 clinical event records across 45,127 patients and 78,043 admissions, normalised to FHIR profiles before ingestion. Four GPT-4o agents answer a question asked in plain English: one reads the intent, one writes schema-validated Cypher, one summarises the rows for a clinician, and one proposes follow-ups from the relationships the answer touched.

On a 50-query Medication / Diagnosis / Risk Assessment benchmark it runs 2.85× faster than the equivalent SQL over the raw tables, with 40% better retrieval relevance.

  • 65%faster than SQL · 490→172 ms
  • 94.3%natural language → Cypher
  • 89.7%summaries rated accurate
  • 8.5 min → 15 svs manual EHR navigation
Neo4jLangChainFHIRGPT-4oRAGAzure OpenAI
How it works

Six MIMIC-IV modules are joined on subject_id and hadm_id, denormalised so graph queries need no runtime joins, then loaded as Patient, Admission, Diagnosis, Medication, Procedure and Test nodes joined by time-stamped edges. NULLs are preserved rather than imputed, so a missing value becomes an absent edge instead of a fabricated relationship.

A question is turned into Cypher by GPT-4o against a schema description, validated for syntax, schema compliance, property existence and query cost before it runs — a failure regenerates with structured feedback. “Medications for patient 10000032” becomes a Patient→Admission→Medication traversal. LangChain embeddings put queries and graph entities in one vector space for similarity search alongside the generated Cypher.

MIMIC-IV is a single hospital’s critical-care data and the benchmark is the project’s own, so the figures above measure this system on this dataset, not clinical readiness.

SkiTrak

A distributed pipeline that ingests ski-lift swipe events, aggregates them per skier, and pushes live leaderboards to WebSocket clients. Stateless Tomcat ingest servers behind an AWS load balancer publish to RabbitMQ with publisher confirms, so a swipe is only acknowledged once the broker has it. A consumer keeps per-resort running totals and a top-20, then fans each changed board out to every server through a pub/sub backplane.

Little's Law and CloudWatch located two ceilings in turn: a publish-channel pool (64 channels at ~13 ms per confirm capped one server near 4,800/s — doubling the pool bought +23% throughput and cut p99 42%), then the broker itself, which saturated while per-server CPU sat at 20%. Failure was tested too: a server killed behind the load balancer, a broker restart, a consumer kill -9 and poison messages.

  • 1Mevents, none lost
  • 7,415/sacross 4 ingest servers
  • 140 msp99 latency
  • 99.95%with a server killed mid-run
JavaRabbitMQWebSocketsAWS EC2 + ALBConcurrencyCloudWatch
How it works

A swipe hits an ingest server behind the load balancer, which validates it, looks up the lift’s vertical and publishes to that resort’s queue, returning 201 only after RabbitMQ confirms. A topic exchange keeps one durable queue per resort, so each resort stays in order and the consumer can hold per-resort state without locks. The consumer deduplicates by event id, updates the top-20, and acks only after the update lands. When a board changes it goes to a fanout exchange, and every ingest server pushes it to its own WebSocket subscribers.

Run as a graduate distributed-systems project at Northeastern: 512 client threads, 4 ingest servers.

AAAI 2026 · HUMAN-CENTRIC MANUFACTURING WORKSHOP

Human-Centric AI for Sustainable Manufacturing: Real-Time Emission-Aware Decision Support in PV Recycling

Saanidhya Vats*, Ishan Chaudhary*, Kiran Gulia, Gesa Beck, Divya Chaudhary · *co-first authors

Recycling operators get no feedback on the greenhouse-gas cost of a process choice until long after the fact, because life-cycle assessment is retrospective. We trained a Random Forest + XGBoost ensemble to predict emissions in real time from energy use, ambient temperature, humidity and process type, so an operator can forecast the impact of an action before running it.

The prototype dataset covers 12 end-of-life PV and e-waste recycling processes, synthesised from IEA-PVPS life-cycle inventories, openLCA impact databases and EPA WARM v15 emission factors — a proof of concept, not a representative sample.

  • 23.38ensemble RMSE
  • 21.55best single model (XGBoost)
  • 108.18linear regression RMSE
  • 12recycling processes
